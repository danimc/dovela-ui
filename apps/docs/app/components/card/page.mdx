# Card

A surface with a compound API. `Card.Header`, `Card.Body` and `Card.Footer` are
plain layout slots — use as many or as few as you need, in any order.

<CodeBlock code={`import { Card } from "@dovela/react";`} />

## Named imports

The parts are exported individually too, if you prefer flat imports over the
dot notation:

<CodeBlock
  code={`import { Card, CardHeader, CardBody, CardFooter } from "@dovela/react";`}
/>

## Server Components

`@dovela/react` is a client package (every component needs React Aria's hooks).
Across the RSC boundary, React hands a Server Component a *reference* to each
export rather than the component itself — and a reference has no properties, so
`Card.Header` resolves to `undefined` and the render fails.

Inside a Server Component, use the flat exports:

<CodeBlock
  code={`// app/page.tsx — Server Component
import { Card, CardHeader, CardBody } from "@dovela/react";

<Card>
  <CardHeader>…</CardHeader>
  <CardBody>…</CardBody>
</Card>;`}
/>

In a Client Component (`"use client"`), both forms work. This is a constraint of
the RSC module boundary, not of this library — every dot-notation component
library has it.

## Accessibility

`Card` renders a plain `<div>` with no implicit role — it is a visual container.
If a card is a meaningful region, give it a heading and an `aria-labelledby`, or
pass `role="group"` with an `aria-label`. Never make the whole card clickable;
put a `Button` or link inside it instead.
